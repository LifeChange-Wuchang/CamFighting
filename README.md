# 相機對戰(Camera Battle)

用手機鏡頭拍下敵隊頭巾來扣血的多人團康遊戲。純網頁(PWA),iPhone 和 Android 都能玩,不用上架 App Store / Google Play。

---

> **Firebase 設定已經填好了**(專案 `camfighting`),部署後可以直接用。
> 但仍要確認兩件事:Realtime Database 的**規則已貼上並發布**、Authentication 的**匿名登入已啟用**。

---

## 一、先做這三件事

### 1. 建立 Firebase 專案

1. 到 [Firebase Console](https://console.firebase.google.com/) 建立新專案
2. 左側選 **Build → Realtime Database → 建立資料庫**
   - 位置建議選 **asia-southeast1(新加坡)**,離台灣最近、延遲最低
   - 先選「測試模式」即可,稍後會換成正式規則
3. 左側選 **Build → Authentication → 開始使用 → 登入方式 → 匿名 → 啟用**
   - 這一步一定要做,否則所有人都會卡在「連線中」
4. 專案設定 → 一般 → 你的應用程式 → 網頁應用程式(`</>`)→ 註冊
   - 複製出現的 `firebaseConfig` 內容

### 2. 填入設定

`js/config.js` 最上面的 `firebaseConfig` **已經填好**你的專案設定,不用改。
換成別的 Firebase 專案時才需要改這裡。

> 這些值本來就會公開在前端網頁裡,不是機密。真正的防護來自下一步的安全性規則。
> 想再加一層,可以到 Google Cloud Console → 憑證 → 該 API 金鑰 → 設定「HTTP 參照網址限制」,
> 只允許你的 Vercel 網域使用。

### 3. 套用安全性規則

Firebase Console → Realtime Database → **規則** 分頁,把 `database.rules.json` 的內容整個貼上去,按發布。

---

## 二、部署

把整個資料夾推上 GitHub,到 [vercel.com](https://vercel.com) 用 GitHub 帳號登入 → Add New Project → 選這個 repo → 不用設定任何 build 指令 → Deploy。

完成後會得到一個 `https://xxx.vercel.app` 網址,這就是給大家掃的網址。

> 相機只能在 https 網址下運作,所以一定要部署後才能測試,不能直接開檔案。

## 三、怎麼玩

**主持人**——請開 `你的網址/host.html`(專屬控台,建議用電腦或平板)
1. 輸入名字 → 建立新房間 → 得到 4 位房號
2. 按「加入QR」讓大家掃描,或直接報房號
3. 在「隊伍設定」填入每隊的頭巾顏色(數值由校色工具產生)。可新增到最多 4 隊
   > 控台網址不要公開給玩家,誰進得去誰就能改設定、結束遊戲
4. 調整遊戲參數,按「依目前人數建議血量」
5. 在「標記點」勾選這場要用哪幾個編號、指定搶佔點或寶箱、取名字
6. 取得 QR 碼:
   - **下載圖片** → 打包成 ZIP,裡面有「含名稱的高解析 PNG」和「純 QR 的 SVG」兩種,
     可以自己排版再影印(PNG 印 6 公分見方約 500 DPI,遠高於印刷需求;SVG 是向量,放多大都不糊)
   - **列印QR碼** → 直接開一份排好版的列印頁,不想自己排版就用這個
   - 各卡片上的「圖」按鈕可以單獨下載某一張
7. 每隊都有人之後按「開始遊戲」。控台會即時顯示各隊血量、據點歸屬與冷卻倒數、戰報、個人戰績

主持人不屬於任何隊伍、不參與計分,也不需要開相機。

**玩家**——開 `你的網址`(或掃主持人的加入QR)。玩家端沒有通往控台的入口。
1. 輸入名字與房號加入 → 選隊伍 → 等開始
2. 遊戲開始後,把準星對準敵隊的臉 → 按快門 → 命中就扣對方血
3. 按「掃描」對準據點 QR 碼:搶佔點要持續對準 5 秒,寶箱掃到就開

**勝負**:時間到時血量最高的一隊獲勝;或當只剩一隊還有血時立即結束。

### QR 碼可以事先印好、永久重複使用

標記 QR 碼的內容是固定編號(M01~M20),**不含房號**。這代表:
- 印一次就好,以後每場活動都能用同一批
- 房間刪掉也不影響,QR 碼不會失效
- 每場只要在控台勾選啟用哪幾號、指定是搶佔點還是寶箱

建議護貝或用透明資料袋裝起來,可以用很多年。

貼的時候注意:**避開會反光的位置**(玻璃、光滑金屬、強光直射),QR 碼反光會掃不到。
貼在霧面牆、木板、紙箱上最穩。

## 四、⚠️ 200 人活動必看

### Firebase 免費方案只允許 100 個同時連線

這是 Spark(免費)方案的硬性上限,**無法透過任何設定提高**。超過的人會連不上。

要辦 200 人的活動,必須升級到 **Blaze(隨用隨付)方案**,上限會變成 200,000 連線。

- Blaze 仍然包含原本的免費額度,你的資料量(純文字、每場幾百筆)遠低於門檻,**實際費用幾乎是 0**
- 但 Blaze **需要綁定信用卡**
- 強烈建議同時到 Google Cloud Console 設定**預算警示**(例如超過 US$5 就寄信通知),避免任何意外

### 第一次載入要下載約 15MB

AI 偵測引擎的體積不小。200 人同時在會場 Wi-Fi 打開網頁 = 瞬間好幾 GB 流量,現場網路很可能塞爆。

**建議做法**:報到時就請大家先掃 QR 碼打開網頁、載入完成,不要等到宣布開始才一起開。或請大家用自己的行動網路。

## 五、頭巾校色(最重要的一步)

打開 `你的網址/calibrate.html`,或從主持人畫面點「開啟頭巾校色工具」。

1. 用**背面鏡頭**(遊戲用的就是背面鏡頭),在**活動當天的場地與燈光**下操作
2. 把黃框對準頭巾布料,按「記錄頭巾」收 5~8 筆——換不同角度、明處暗處各收幾筆
3. 把黃框對準**額頭皮膚、頭髮、牆壁、常見衣服顏色**,按「記錄皮膚/背景」收 5~8 筆
4. 按「產生設定」,工具會算出一組既涵蓋頭巾、又能排除皮膚背景的門檻值
5. 把產生的那一行貼回 `js/config.js` 的 `DETECT.teamColors`

**為什麼要收「皮膚」樣本?** 取樣區塊就在額頭上方。萬一有人沒戴頭巾,系統取到的會是皮膚。
皮膚的色相約 10~30 度、飽和度 0.2~0.45,和淡紅色高度重疊——門檻放太鬆的話,沒戴頭巾的人會被判成紅隊。
工具如果警告「無法排除」,代表那個顏色天生就和皮膚太接近,換一條更鮮豔的比調參數有效。

**挑頭巾的建議**:選**飽和度高、顏色深**的。淡色系(水藍、粉紅、米色、淺灰)最容易出問題,
因為它們接近灰白,和皮膚、牆面、日光燈下的白牆都不好分。深藍配大紅是穩定的組合。

**可以自拍校色嗎?** 可以按「切換鏡頭」用前鏡頭,方便你自己戴著測。
但前後鏡頭的白平衡不完全一樣,**最後請務必用背面鏡頭再確認一次**,因為遊戲跑的是背面鏡頭。

## 六、遊戲平衡

### 血量上限與開場血量是分開的

| 欄位 | 意義 |
|---|---|
| 血量上限 | 回血回不過這個數字 |
| 開場血量(%) | 開場時是上限的百分之幾,預設 **70%** |

**為什麼開場不設滿血?** 因為滿血開場的話,據點回血在前期完全沒有作用——回不上去。
等於前段時間的地圖控制權是白搶的。留一段空間,搶據點從第一分鐘就有價值。

以上限 4290 為例:

| 開場 % | 開場血量 | 回血空間 | 效果 |
|---|---|---|---|
| 100% | 4290 | 0 | 前期搶據點完全沒用 |
| 90% | 3861 | 429 | 持有 2 點約 5 分鐘就回滿,之後失效 |
| **70%** | **3003** | **1287** | 持有 2 點約 15 分鐘回滿,全場都有意義 |
| 50% | 2145 | 2145 | 回血空間很大,但開場很脆弱、容易被速推 |

想讓據點更關鍵就把開場 % 調低,想讓遊戲更偏純槍戰就調高。

### 血量一定要依人數調整

血量預設值只適合小規模測試。人數變兩倍,總傷害輸出就變兩倍,血量沒跟著調的話遊戲會瞬間結束。

控台有「**依目前人數建議血量**」按鈕:

```
需要的開場血量 = 每隊人數 × 分鐘數 × 1.5
血量上限       = 開場血量 ÷ 開場百分比
```

那個 1.5 是「每人每分鐘平均命中 1.5 次」的保守估計。場地小、人擠人會更高,場地大會更低。
按鈕旁邊會即時顯示「開場 ○○○ / 上限 ○○○ · 回血空間 ○○○」,調的時候看那個數字最直觀。
**強烈建議正式開打前先跑一場 5 分鐘的測試場**,看血量掉多快,再回頭調整。

### 據點:佔領當下回一次,持有期間持續回

這是整場遊戲最重要的戰術目標,分兩段:

| 參數 | 意義 | 預設 |
|---|---|---|
| 佔領當下回血 | 搶下據點的瞬間立刻回復的血量 | 1% |
| 持有每分鐘回血 | **每持有一個據點**,每分鐘持續回復的血量 | 1% |

持有越多、守越久,回得越多。以 20 分鐘的場次估算,獨佔的總回血量是:

| 持有據點數 | 20 分鐘總回血 |
|---|---|
| 1 個 | 最大血量的 20% |
| 2 個 | 40% |
| 3 個 | 60% |
| 4 個 | 80% |

這個量級和整場的總傷害輸出相當,所以**地圖控制權會直接決定勝負**,而不只是加減分。

**佔領冷卻預設為 0**,兩隊可以隨時互搶。如果現場發現有人靠反覆互搶來刷「佔領當下回血」,
在控台把冷卻設成 15~30 秒就能擋掉。

> ⚠️ **持續回血由主持人控台負責結算,遊戲期間請保持控台分頁開著。**
> 控台若被關掉或裝置休眠,回血會暫停;重新開啟後會把中間漏掉的份量一次補上,不會少算。

### 回血都是百分比

所有回血都是「最大血量的百分之幾」,所以換人數時不用重調。

| 寶箱獎勵 | 機率 | 效果 |
|---|---|---|
| 補給箱 | 20% | 我方回復 3% 血量 |
| 急救包 | 30% | 我方回復 1.5% 血量 |
| 空襲指令 | 20% | 敵隊直接損失 2% 血量 |
| 火力全開 | 20% | 接下來 30 秒你的傷害加倍 |
| 空箱子 | 10% | 沒東西 |

寶箱兩隊都能開,所以整體是中性的,價值在搶時機和卡冷卻。
如果想讓遊戲更偏進攻、更快分出勝負,可以把 `js/config.js` 的 `CHEST_REWARDS` 裡回血那兩項的 `pct` 調低。

### 防刷分機制

- **開火冷卻**(預設 3 秒):沒打中也一樣進冷卻
- **據點冷卻**(預設 0 秒,可調):設定後可防止兩隊互搶同一個點來刷「佔領當下回血」
- **寶箱冷卻**(預設 180 秒):防止有人守著箱子一直開

## 八、房間管理

控台的進入畫面會列出**你建立過的房間**,顯示房號、狀態、人數與建立時間,可以直接「接手」回去或刪除。
下方的「清除已結束與已消失的房間」會一次刪掉所有已結束的場次,大廳中與進行中的不會動到。

### 會不會累積一堆垃圾資料?

建新房間**不會**自動刪掉舊的,會一直累積。但容量上幾乎不需要擔心:

| 項目 | 大小 |
|---|---|
| 一個跑完 200 人完整場次的房間(含戰報) | 約 100 KB |
| Firebase 免費方案儲存空間 | 1 GB |

等於要累積上萬場才會有感。不過為了不要越用越亂,還是建議活動結束後順手清一下。

### ⚠️ 房間清單綁定「這台裝置的這個瀏覽器」

主持人身分是用 Firebase 匿名帳號認證的,而匿名帳號存在瀏覽器本機。這代表:

- **換裝置、換瀏覽器、開無痕、清除瀏覽資料** → 會拿到新的匿名身分
- 新身分看不到舊房間清單,而且因為不再是原主持人,**連刪除都做不到**

所以:**請固定用同一台裝置、同一個瀏覽器主持,活動期間不要清瀏覽資料**。

真的變成孤兒房間了也有救,你是專案擁有者:
Firebase Console → Realtime Database → 直接在資料樹上找到那個房號手動刪除即可。

## 九、已知限制

| 限制 | 說明 |
|---|---|
| 分不出被拍到的是誰 | 系統只認「人臉 + 隊伍顏色」,不做身分辨識。所以只能扣隊伍血量,無法做個人淘汰或個人復活機制。這也代表你**不需要蒐集任何人的臉部資料**,對隱私反而是好事。 |
| 可以重複拍同一個人 | 因為認不出是誰。用「開火冷卻」來抑制洗分,預設 3 秒。 |
| 前端計分可被竄改 | 懂技術的人理論上可以改分數。安全性規則已限制血量範圍與寫入權限,但沒有伺服器端裁判。對公司/教會團康活動而言足夠,不適合有實質獎金的正式比賽。 |
| 翻拍照片也可能被判定成功 | 拿別人照片給鏡頭拍有機會過關。一般團康不需要防偽造,列為已知限制。 |
| iOS「加到主畫面」相機不穩 | 建議直接在 Safari 分頁裡玩,不要加到主畫面。 |
| 沒戴頭巾的人可能被誤判 | 額頭取樣可能取到皮膚。務必用校色工具收「皮膚樣本」把這個排除掉。 |
| 主持人身分綁瀏覽器 | 換裝置或清除瀏覽資料後會失去對舊房間的控制權,只能從 Firebase Console 手動刪。 |
| 誤傷隊友不扣血 | 拍到自己隊伍顏色時會顯示「那是隊友」,不計分也不扣血,但一樣進入開火冷卻。 |

## 十、檔案結構

```
index.html            玩家端遊戲
host.html             主持人控台(桌機/平板友善)
calibrate.html        頭巾校色工具
styles.css            樣式(含橫向模式)
database.rules.json   Firebase 安全性規則
js/
  config.js           ★ Firebase 設定(遊戲參數已移到控台線上設定)
  host.js             主持人控台邏輯
  qrimage.js          QR 碼圖片輸出(PNG / SVG / ZIP)
  detect.js           相機、人臉偵測、頭巾顏色判定
  game.js             Firebase 連線與遊戲規則
  scan.js             QR Code 掃描
  ui.js               畫面切換與互動
  calibrate.js        校色工具邏輯
```

除了 Firebase 設定之外,幾乎所有東西(隊伍顏色、血量、冷卻、標記點)都能在主持人控台線上調,不用改程式碼。
