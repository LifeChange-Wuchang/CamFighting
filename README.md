# 相機對戰(Camera Battle)

用手機鏡頭拍下敵隊頭巾來扣血的多人團康遊戲。純網頁(PWA),iPhone 和 Android 都能玩,不用上架 App Store / Google Play。

---

## 一、先做這三件事

### 1. 建立 Firebase 專案

1. 到 [Firebase Console](https://console.firebase.google.com/) 建立新專案
2. 左側選 **Build → Realtime Database → 建立資料庫**
   - 位置建議選 **asia-southeast1(新加坡)**,離台灣最近、延遲最低
   - 先選「測試模式」即可,稍後會換成正式規則
3. 左側選 **Build → Authentication → 開始使用 → 登入方式 → 匿名 → 啟用**
   - 這一步一定要做,否則所有人都會卡在「連線中」
4. 專案設定 → 一般 → 你的應用程式 → 網頁應用程式(`</>`)→ 註冊
   - 複製出現的 `firebaseConfig` 內容

### 2. 填入設定

打開 `js/config.js`,把最上面的 `firebaseConfig` 換成你剛複製的內容。

> 這些值本來就會公開在前端網頁裡,不是機密。真正的防護來自下一步的安全性規則。

### 3. 套用安全性規則

Firebase Console → Realtime Database → **規則** 分頁,把 `database.rules.json` 的內容整個貼上去,按發布。

---

## 二、部署

把整個資料夾推上 GitHub,到 [vercel.com](https://vercel.com) 用 GitHub 帳號登入 → Add New Project → 選這個 repo → 不用設定任何 build 指令 → Deploy。

完成後會得到一個 `https://xxx.vercel.app` 網址,這就是給大家掃的網址。

> 相機只能在 https 網址下運作,所以一定要部署後才能測試,不能直接開檔案。

---

## 三、怎麼玩

**主持人**
1. 開網址 → 輸入名字 → 建立新房間 → 得到 4 位房號
2. 按「加入QR」讓大家掃描,或直接報房號
3. 在主持人設定裡調整血量、時間、冷卻等參數
4. 新增據點(搶佔點 / 寶箱)→ 按「列印所有據點QR碼」→ 印出來貼在現場
5. 兩隊都有人之後,按「開始遊戲」

**玩家**
1. 掃 QR 或輸入房號加入 → 選隊伍 → 等開始
2. 遊戲開始後,把準星對準敵隊的臉 → 按快門 → 命中就扣對方血
3. 按「掃描」對準據點 QR 碼:搶佔點要持續對準 5 秒,寶箱掃到就開

**勝負**:時間到時血量高的一隊獲勝,或任一隊血量歸零立即結束。

## 四、⚠️ 200 人活動必看

### Firebase 免費方案只允許 100 個同時連線

這是 Spark(免費)方案的硬性上限,**無法透過任何設定提高**。超過的人會連不上。

要辦 200 人的活動,必須升級到 **Blaze(隨用隨付)方案**,上限會變成 200,000 連線。

- Blaze 仍然包含原本的免費額度,你的資料量(純文字、每場幾百筆)遠低於門檻,**實際費用幾乎是 0**
- 但 Blaze **需要綁定信用卡**
- 強烈建議同時到 Google Cloud Console 設定**預算警示**(例如超過 US$5 就寄信通知),避免任何意外

### 第一次載入要下載約 15MB

AI 偵測引擎的體積不小。200 人同時在會場 Wi-Fi 打開網頁 = 瞬間好幾 GB 流量,現場網路很可能塞爆。

**建議做法**:報到時就請大家先掃 QR 碼打開網頁、載入完成,不要等到宣布開始才一起開。或請大家用自己的行動網路。

---

## 五、活動前一定要測的事

- [ ] **用實際的頭巾、在活動當天的場地和燈光下測試顏色判定**。這是最容易出問題的環節。
      如果判定不準,調整 `js/config.js` 裡 `DETECT.teamColors` 的色相/飽和度/亮度門檻。
      遊戲中每次開火都會顯示實際取樣到的數值,照著調就行。
- [ ] 用現場會出現的 iPhone 機型各測一次(iOS 相機相容性問題常常是版本特定的)
- [ ] 確認場地各角落光線都夠,陰影處特別容易誤判
- [ ] 印好據點 QR 碼,貼在**不會反光、光線充足**的位置
- [ ] 提醒大家把手機電量充飽,並先關閉省電模式

## 六、已知限制

| 限制 | 說明 |
|---|---|
| 分不出被拍到的是誰 | 系統只認「人臉 + 隊伍顏色」,不做身分辨識。所以只能扣隊伍血量,無法做個人淘汰或個人復活機制。這也代表你**不需要蒐集任何人的臉部資料**,對隱私反而是好事。 |
| 可以重複拍同一個人 | 因為認不出是誰。用「開火冷卻」來抑制洗分,預設 3 秒。 |
| 前端計分可被竄改 | 懂技術的人理論上可以改分數。安全性規則已限制血量範圍與寫入權限,但沒有伺服器端裁判。對公司/教會團康活動而言足夠,不適合有實質獎金的正式比賽。 |
| 翻拍照片也可能被判定成功 | 拿別人照片給鏡頭拍有機會過關。一般團康不需要防偽造,列為已知限制。 |
| iOS「加到主畫面」相機不穩 | 建議直接在 Safari 分頁裡玩,不要加到主畫面。 |

## 七、檔案結構

```
index.html            所有畫面的 HTML
styles.css            樣式(含橫向模式)
database.rules.json   Firebase 安全性規則
js/
  config.js           ★ Firebase 設定與所有可調參數
  detect.js           相機、人臉偵測、頭巾顏色判定
  game.js             Firebase 連線與遊戲規則
  scan.js             QR Code 掃描
  ui.js               畫面切換與互動
```

想調整遊戲平衡,絕大多數情況只需要動 `js/config.js`。
